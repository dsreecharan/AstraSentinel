# MVP architecture and installation decisions

The [implementation blueprint](../IMPLEMENTATION_BLUEPRINT.md) sets product scope. The [v1 contracts](CONTRACTS.md) define the behavior at the interfaces.

| Decision | Reason and trade-off |
| --- | --- |
| OpenCV MP4 replay and Ultralytics YOLO26n with ByteTrack | A permissioned file makes the same demo reproducible. A dedicated worker isolates sequential decode/tracking and expensive model calls from HTTP handlers. Test the chosen aerial footage for small people and occlusions. |
| Latest-frame MJPEG | The browser can show annotated JPEGs with minimal setup. One bounded frame store supports slow viewers without queuing old frames. Repeated JPEG encoding and bandwidth make it a local demo transport. MediaMTX belongs to the later RTSP and WebRTC/HLS work. |
| SQLite, SQLAlchemy, and Alembic | A local file keeps setup small while supporting transactions, constraints, and schema migrations. Use a writable local directory, short transactions, and enable foreign keys for each connection. PostGIS becomes relevant when spatial queries or deployment needs justify it. [SQLite foreign keys](https://www.sqlite.org/foreignkeys.html) |
| REST plus WebSocket notifications | SQLite is the durable source of truth. Broadcast after commit and fetch current REST state on reconnect. Redis Streams belongs to a later service split with durable consumer requirements. |
| Calibrated world coordinates or explicit image-space context | Stable, calibrated footage can support a geographic marker. A moving or uncalibrated clip can still demonstrate restricted image regions. MapLibre renders validated world features and keeps image regions in the video pane. |

## Runtime dependencies and installation risks

| Area | Required for the MVP | Risk and verification |
| --- | --- | --- |
| Backend and tests | CPython 3.11, FastAPI, Pydantic, Uvicorn with WebSocket support, SQLAlchemy, Alembic, pytest, and HTTPX/TestClient. SQLite comes with Python. | Use a project virtual environment and interpreter-qualified commands. On this Windows machine, plain `py` selects 3.14. Create the venv with `py -3.11 -m venv .venv` and use `.venv\Scripts\python.exe -m pip` and `.venv\Scripts\python.exe -m pytest`. Linux/WSL uses `python3.11 -m venv .venv` and `.venv/bin/python`. Verify a clean migration and reopen a real file-backed test DB. |
| OpenCV and MP4 | One compatible `cv2` wheel, NumPy, and the selected permissioned MP4. Prefer the normal `opencv-python` dependency when using the normal Ultralytics distribution. | Resolve one OpenCV distribution and verify the NumPy ABI and Windows DLL prerequisites. On Windows N/KN check the Media Feature Pack if imports fail. Prove actual decode, dimensions, timestamps, JPEG encode, and EOF on the exact demo file. An MP4 extension alone gives no codec guarantee. FFmpeg CLI is optional for diagnostics or approved transcoding. [OpenCV wheel installation](https://pypi.org/project/opencv-python/) |
| Detector and tracker | A tested `ultralytics` release with YOLO26 support, matching `torch` and `torchvision` wheels, official `yolo26n.pt`, shipped `bytetrack.yaml`, and the tracker dependencies of the chosen release. | Verify 64-bit Python 3.11 wheel availability and test the CPU profile first. For optional NVIDIA acceleration use the PyTorch selector and verify driver compatibility and `torch.cuda.is_available()`. Avoid hard-coded CUDA versions. Inspect the pinned tracker for dependencies such as `lap` that it may otherwise attempt to install on first use. Pin that dependency and prove actual tracker IDs across successive frames. [PyTorch installation](https://pytorch.org/get-started/locally/) · [Ultralytics installation](https://docs.ultralytics.com/quickstart) · [Tracker dependency source](https://github.com/ultralytics/ultralytics/blob/main/ultralytics/trackers/utils/matching.py) |
| Weights and offline operation | A trusted local copy of the official detection weights, a known checksum, and a configured tracker. | Fetch from the official release during explicit setup and verify the expected artifact. Keep weights and caches out of Git by default. Validate the configured file before model load, check for implicit first-use downloads and dependency installs, and test actual replay with network access disabled. Prove a missing/bad file produces an error. [YOLO26 model docs](https://docs.ultralytics.com/models/yolo26) · [Ultralytics tracking docs](https://docs.ultralytics.com/modes/track) |
| Frontend | Node.js and npm, React, React DOM, TypeScript, Vite with a React plugin, and MapLibre GL JS. | Match Node to the pinned Vite `engines` and record both versions. Use `npm.cmd` in PowerShell if script execution policy blocks the shim. Commit a lockfile and verify `npm ci`, typecheck and build with a clean install. [Vite runtime requirements](https://vite.dev/guide/) |
| Map and browser | WebGL-capable browser and a compatible MapLibre style. A basemap needs an approved style, tiles, fonts or glyphs, and attribution as applicable. | Test on the demo browser. Verify credentials, quotas, CORS, attribution, and offline behavior if using a remote provider. Support a local minimal style or an explicit map-error state so evidence, review, and audit remain accessible. Keep restricted footage or incident payloads away from external map services. [MapLibre GL JS setup](https://maplibre.org/maplibre-gl-js/docs/) · [Source attribution](https://maplibre.org/maplibre-style-spec/sources/) |

At bootstrap, pin the validated Python dependencies per supported platform/profile, commit the npm lockfile, and document package and artifact setup in the README. Keep basic API/unit tests installable without model weights, CUDA, or GPU access. Verify the real-inference extra separately with `pip check`, imports, model load, and a short end-to-end replay. This planning task defines the inventory and acceptance checks. Exact package versions depend on clean-install verification.

## Asset and license readiness

- **Inference.** Ultralytics states that its code and pretrained YOLO models default to AGPL-3.0, with an Enterprise option for use under separate terms. Record the license choice for the integrated demo, retain required notices, and review corresponding-source obligations for distribution or network access. Record the exact package, model origin/checksum, tracker configuration and terms in the inventory. [Ultralytics licensing FAQ](https://www.ultralytics.com/license)
- **Footage and evidence.** Select and record one permissioned MP4, its checksum, and evidence/display and redistribution terms before the real demo gate. Keep the original local or provide an authorized download link when redistribution is restricted. Treat screenshots and recordings as separate sharing uses when checking the permissions.
- **Other libraries and basemaps.** Capture licenses from resolved package and asset versions at implementation time. Track basemap-provider terms and attribution separately from MapLibre's library license.
